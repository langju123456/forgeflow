# 可回答性判断：预先登记

写于第一次在本语料上调用 `qwen3:8b` 之前，与判断代码、运行脚本同一次提交；提交时间就是登记时间。
机器可读的版本是 [preregistered.json](preregistered.json)，运行脚本读它、核对提示词哈希，不一致就不跑。之后不改本文件，改动另起新版本并保留旧结果。

## 要回答的问题

S2 混合检索把内容正例 Recall@5 提到 93.33%，但“无答案问题返回非空上下文”仍是 1/3；事后的阈值扫描说明余弦下限分不开“弱相关”和“无答案”
（无答案题 Q32 的最高相似度 0.4633，比两道有答案题的目标还高）。
检索之后加一步：逐条判断“这条结果是否真的回答了这个问题”，并要求引用原文。这能不能让无答案问题正确返回空，同时不明显丢掉有答案问题的来源、不放宽权限？

## 固定不变的部分

- **语料、冻结题集、评测器**：S2 的 `dataset.json`、`evaluator.py` 等逐字节核对 S2 `freeze.json`；评测器原样导入，两种模式用同一套打分（找回、引用、越权追踪、时延）。
- **新留出题集**：`heldout.json`，32 题，提交 `ac08407`，哈希在 `freeze.json`，运行前后各核对一次。
- **检索**：S2 登记的混合检索原样：`bge-m3`、余弦下限 0.50、RRF k = 60、top_k = 5。
- **权限顺序**：Store 先按角色、密级、scope 过滤 → 排序 → 逐条重新授权引用（`RankedKnowledgeService`）→ 然后才轮到判断步骤。
  判断步骤只拿到检索已经返回给这个调用者的结果，只能删，不能加、不能改；`context.py` 不动。

## 两种模式

| 模式 | 做法 |
|---|---|
| hybrid | S2 混合检索原样 |
| hybrid+answerability | 同一检索结果交给 `forgeflow.answerability.AnswerabilityGate`，只保留被判定为“回答了问题”且引文核对通过的条目 |

## 判断步骤的设置（现在定，不看结果调）

- **模型**：本机 Ollama 的 `qwen3:8b`（传输检查时 `ollama list` 显示 ID `500a1f067a9f`，Ollama 0.32.1，Apple M4 MacBook Air），不出本机。实际 digest 写进每次运行的报告。
- **调用**：OpenAI 兼容接口 `/v1/chat/completions`；`reasoning_effort: "none"` 关闭思考；`temperature` 0，`seed` 0，`max_tokens` 512；
  `response_format` 为严格 JSON schema：`{"verdicts": [{"passage": 整数, "answers": 布尔, "quote": 字符串}]}`。回环地址不走代理。
- **提示词**：版本 `answerability-v1`，哈希 `423bb48b0d3d7ab87f3cb438efc9b7de0aa248450db57a371a05b1f0a9098457`
  （系统提示、用户模板、schema、引文最短长度、标识符规则一起算）。每次检索只调用一次模型，所有命中编号后一起判断。
- **接受一条的条件**：模型说 `answers: true`，且引文去掉首尾空白后至少 6 个字符，并且**逐字**出现在这一条的内容里（大小写、标点都不归一化）。
  说“是”但引文不在原文里，记为 `QUOTE_NOT_IN_PASSAGE`，这一条不保留。模型漏判的条目按“否”处理。
- **没有任何一条被接受**：返回空，状态 `NO_ANSWER_IN_KNOWLEDGE_BASE`（知识库里没有答案）。
- **出错一律关闭**：不是严格 JSON、结构不对、引用不存在的段落号、同一段落两个判断、输出被截断、连接失败，都返回空，状态 `GATE_ERROR`。
  **评分时 `GATE_ERROR` 对有答案题和无答案题都算错**，不能靠出错“蒙对”无答案题。
- 允许去掉 Qwen3 偶尔在开头输出的 `<think>…</think>` 块（不算判断内容）。
- **标识符查询不调用模型**：整条查询就是一个带连字符的标识符（如 `evt-boot`、`NEVER-APPROVED-P1`）时，只保留 id 与之相同（不分大小写）或内容逐字含有它的条目。
  这类查询是按编号找文档，不是提问。这条规则是知道冻结 47 题里有 12 道纯 ID 查询之后定的，所以冻结集上这部分结果不能当它的证据；
  新留出集没有 ID 查询，主结果不受它影响。
- **重复次数**：hybrid 5 次（同冻结协议）；hybrid+answerability 2 次，每次都真实调用模型，按评测器惯例取第一次打分，两次是否一致单独报告。
  预热：每题先检索一次（填文档向量缓存，与 S2 相同）；模型先用一句与语料无关的话加载一次，不计入结果。

## 写本文件前唯一的一次模型调用

为确认接口和关闭思考的方式可用，在同一台 Mac 上用一段**与语料无关**的面包店示例（两段话、一个问题）各调用了一次 OpenAI 兼容接口（`reasoning_effort: "none"`，两次）和原生接口（`think: false`）：
都返回了严格 JSON、没有思考内容，单次约 6 秒（首次 12 秒含加载）。没有用到任何语料文档或题目。记录在 mac-bridge 任务 `20261105-031224-qwen-smoke`。

## 指标

主集是新留出集（32 题）；冻结 47 题已经看过，只作探索性对照。

| 指标 | 定义 |
|---|---|
| 有答案题 gold 找回 | 最终结果里出现任一 gold 来源的题数 / 有答案题数（留出 18；冻结 37 个正例，另报其中 30 个内容正例） |
| 无答案题正确为空 | 结果为空且不是 `GATE_ERROR` 的题数 / 无答案题数（留出 12；冻结 3） |
| 越权对照正确为空 | 同上，越权对照题（留出 2；冻结 7） |
| 越权（必须全为 0） | 评测器的泄漏、越权候选行、越权引用行；另一层不过滤的审计记录里的越权行和引用；判断步骤看到的内容不在调用者可读范围内的条数；判断步骤返回的条目不是检索返回的同一对象的条数 |
| 时延 | 评测器测的端到端检索时延（含判断步骤）中位数 / p95；模型调用时延单独报告 |
| 其他 | `GATE_ERROR` 次数、各类判断理由计数（含引文被拒）、重复是否一致、逐题漏检和误留列表 |

冻结集上 hybrid 一列应与 S2 [RESULTS.md](../../s2/evaluation/hybrid/RESULTS.md) 的混合结果一致（同一代码、同一题集），作为一致性核对。

## 事先定下的判断规则

判断步骤可以作为默认候选，当且仅当同时满足：

1. **越权**：两个题集、两种模式，上表列出的所有越权计数都为 0；
2. **无答案题**：在留出集上，hybrid+answerability 正确为空的题数比 hybrid **至少多 4 题**（共 12 题）；
3. **有答案题**：在留出集上，hybrid+answerability 的 gold 找回题数比 hybrid **最多少 1 题**（共 18 题）。

任何一条不满足，就如实报告，默认仍是不加判断的 hybrid。冻结 47 题不参与第 2、3 条。时延只报告，不设门槛（笔记本单机数字）。

## 不能宣称的

- 留出集与代码出自同一作者，题量小、合成；有答案题 1 题 = 5.6 个百分点，无答案题 1 题 = 8.3 个百分点。
- 不代表真实资料、真实用户问题、别的模型或生产时延。
- 这一步只判断“检索结果里有没有能回答的那条”，不生成答案；不报告回答质量或幻觉率。
- 跑完这次，留出集也就用过了。之后若改提示词、阈值或规则，必须另建新题集再验证。
