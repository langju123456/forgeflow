## 要回答的问题

[上一次运行](../RESULTS.md) 里混合检索的页级 Recall@5 是 18/28：中文问中文报告只有 3/10，另有几题找到了 gold 页，但排进前 5 的是同页上不含答案的那一块。
在混合检索之后加一步重排（cross-encoder 把问题和每条候选放在一起读，重新排序），正确的页能不能多进前 5，同时权限不放宽？
这次只测检索，不调用回答模型和判断模型。

## 这套题已经用过

- 合成 47 题（`preparation/s2/evaluation`）也已经用过（混合检索对比、可回答性判断的探索性对照），这次只当护栏，登记在 [那边的文件](../../../s2/evaluation/rerank/PREREGISTRATION.md) 里。

## 固定不变的部分

- **题集、来源、PDF、解析和入库、两份受限副本、两道无权提问**：全部照 [上一次的登记](../PREREGISTRATION.md)（`../preregistered.json`，sha256 `1a1f2838…`）原样，由 `run_qa.py` 里同一段代码完成；`run_qa.py`、`questions.json`、`sources.json` 不改。
- **混合检索**：`bge-m3`（本机 Ollama）、余弦下限 0.50、RRF k = 60、top_k = 5，向量缓存的做法不变。
- **权限顺序**：Store 先按角色、密级、scope 过滤 → `_active_rows` 复核 → 混合检索排序 → 重排 → 逐条重新授权引用（`RankedKnowledgeService.search` 和 `_cited_hits` 不改）。
  重排模型在本进程内推理，只拿到已经通过授权的行的原文；推理时不联网。

## 重排的设置（现在定，不看结果调）

| 项 | 登记值 |
|---|---|
| 模型 | `BAAI/bge-reranker-v2-m3`，用 sentence-transformers 的 `CrossEncoder` 在本机加载，`device='mps'`，float32，不量化 |
| 候选数 N | 混合检索（RRF）排出的前 30 条；不足 30 条就全部重排 |
| 输入 | 问题原样；候选是 Store 里那一行的全文，包含 `[source] 文件 \| 页 [bbox]` 首行 |
| max_length | 1024 个 token（问题和候选合在一起；超出时由分词器从较长的一段末尾截断）。被截断的条数单独报告 |
| 分数 | 模型输出的原始 logit，不过 sigmoid，只用来排序 |
| 分数阈值 | 不设。重排只改顺序，不删任何一条；第 30 条之后的候选按原顺序排在后面 |
| 同分 | 保持混合检索原来的先后 |
| 批大小 | 8（只影响速度） |
| top_k | 5 |

- 模型版本：写本文件的环境连不上模型仓库，没法在登记时钉住版本号；运行时把实际下载的快照 commit、sentence-transformers / transformers / torch 版本写进报告。
- 只跑一次，不重复；时延就是这一次的数字。

## 指标

| 指标 | 定义 |
|---|---|
| 页级 Recall@5 | 有答案题（28）：前 5 条里有一条的 `[source]` 首行是 `<doc>.pdf` 且页码落在题目的 `pages` 里。混合检索和加重排各报一次，逐题列出新增和丢掉的题 |
| MRR@5 | 有答案题：前 5 条里第一条落在 gold 页的名次的倒数，没有记 0，28 题取平均。封存运行的前 5 条按这个定义算是 0.4298（登记时从封存报告算出） |
| 前 N 候选上限 | 有答案题：混合检索前 30 条候选里有没有落在 gold 页的行。这是重排之后 Recall@5 的上限；另报 gold 页第一次出现在第几名 |
| 语言切片 | 同语言（20）/ 跨语言（8），以及中文问中文报告（10）、英文问英文报告（10）、跨语言（8）三分。封存运行是 13/20、5/8 和 3/10、10/10、5/8 |
| 越权计数（必须全为 0） | 每次检索 Store 返回的行里调用者无权读的、来自两份副本的；引用里无权读的；前 5 条结果里来自副本的；送进重排模型的候选里含副本标记的、不在调用者可读范围内的；送进嵌入模型的文字里含副本标记的。两道无权提问 X01、X02：返回 0 条，重排模型 0 次调用 |
| 时延 | 每题：混合检索、加重排后的整次检索、其中重排模型推理各自的中位数 / p95 / 最大值；模型加载和预热另报，不计入每题时延 |

无答案题（12）没有 gold 页，不进 Recall 和 MRR；重排不设阈值，不会让结果变空，这 12 题只计入越权计数和时延。
每题前 30 条候选的 RRF 名次、重排分数、是否 gold 页都存进报告；基于它的任何分析（例如分数阈值）只算探索性结果，不替换主结果。

## 事先定下的判断规则

重排可以接进产品（`report_desk.py::_build_service` 改成混合 + 重排），当且仅当同时满足：

1. **年报题**：加重排后的页级 Recall@5 比同一次运行里复现的混合检索至少多对 3 题，即不低于 21/28；
2. **越权**：上表的越权计数全部为 0，X01、X02 都返回空；
3. **护栏**：合成 47 题上不退步、越权为 0（规则见 [那边的登记](../../../s2/evaluation/rerank/PREREGISTRATION.md)）。

任何一条不满足，就如实报告，记“不采用”，`_build_service` 不改。MRR、候选上限、语言切片和时延只报告，不设门槛。
在规则通过之前，`_build_service` 不动。

## 不能宣称的

- 题目、gold 页和被测代码出自同一作者；这 40 题已经用过，加重排这个想法来自上一次的结果。
- 28 道有答案题，1 题 = 3.6 个百分点；规则里的“多 3 题”是 10.7 个百分点，只跑一次，没有置信区间。
- 页级 Recall 把“找到 gold 页上不含答案的那一块”也算命中，上一次已经说明它高估了答案所在那一行的找回；gold 页表不全的 3 道题（M03、A01、C01）照旧按冻结的题集算。
- 候选上限低的题，重排救不回来：gold 页没进前 30，就要改分块、中文词法或候选数，那是另一次登记的事。
- 时延是 M4 MacBook Air 单机、MPS、无并发的数字，不代表服务器部署。
- 没有调用回答模型，所以不报告答对多少、自信答错多少；重排对回答的影响要另测。
