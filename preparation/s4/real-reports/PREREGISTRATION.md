# 真实年报问答：预先登记

写于第一次在这四份年报上做检索、调用嵌入模型或问答模型之前，与问答代码、运行脚本同一次提交；提交时间就是登记时间。
机器可读的版本是 [preregistered.json](preregistered.json)，运行脚本 `run_qa.py` 读它，核对题集、来源清单、每个 PDF、两个提示词哈希和模型设置，不一致就不跑。
之后不改本文件，改动另起新版本并保留旧结果。

在此之前，这四个 PDF 只被解析过（`table_probe.py` 核对表格数字，见 `runs/after_fixes.json`），没有做过检索，也没有给任何模型看过。

## 要回答的问题

S2/S3 的检索和可回答性判断都是在合成语料上测的。换成四份真实公开年报（茅台、宁德时代 2025 年报中文，腾讯 2025 年报和苹果 FY2025 10-K 英文，共 737 页），
从 PDF 解析、入库、混合检索到带引用的答案，整条链路能答对多少、在报告里没有的问题上会不会编一个带引用的数字、权限有没有漏；
检索之后加不加可回答性判断，结果差多少。

## 固定不变的部分

- **题集**：`questions.json`，40 题（有答案 28，其中 8 道跨语言；无答案 12），提交 `33bd43cebb54cfc67cc6e52f476d1f89f3ab328a` 冻结，
  sha256 `68f83bf6ca3979ce2d2e359d2167b0f4e1ddbbbf81bd60d63233c020dafbec2a`。运行前后各核对一次。
- **来源**：`sources.json`（sha256 `e69cd9b127a8778c12f71aaf303b4401c9f5ba77be338df9b0cb3a6a545f2942`），四个 PDF 逐个按其中的 sha256 核对。
- **解析和入库**：`forgeflow.pdf_ingest.ingest_pdf` 原样（正文块上限 900 字符，表格按逻辑表成行），经 `ingest_into_store` → `Store.put_document` 写入一个 SQLite Store；
  一个 scope（`s4-real / annual-reports / finreports-2025`），角色 `finance`，密级 1。
- **检索**：S2 登记的混合检索原样：`bge-m3`、余弦下限 0.50、RRF k = 60、top_k = 5。嵌入按 16 条一批调用，向量按（模型、模型 digest、文本）的 sha256 缓存在本机磁盘，
  缓存命中与否返回同样的 float64 向量。第一次检索前先用固定查询 `annual report` 检索一次，把分析员可读的全部行嵌入一遍，这段时间单独报告，不计入每题时延。
- **权限顺序**：Store 先按角色、密级、scope 过滤 → 排序 → 逐条重新授权引用（`RankedKnowledgeService`，`context.py` 不动）→ 然后才轮到判断步骤和回答步骤；
  这两步都只拿到检索已经返回给这个调用者的结果。
- **两种模式共用同一次检索**：每题只检索一次，两种模式拿同一组 top-5 结果，所以差别只来自判断步骤。

## 两种模式

| 模式 | 做法 |
|---|---|
| hybrid | 混合检索 top-5 → 带引用回答 |
| hybrid+answerability | 同一组 top-5 → `AnswerabilityGate`（S3 原样，提示词 `answerability-v1`）→ 只把保留下来的条目交给带引用回答；一条不剩就直接“没有答案”，不调用回答模型 |

每题模型调用的顺序固定：检索 → hybrid 的回答 → 判断 → 判断之后的回答。只跑一次（不重复）；温度 0、seed 0，但本次不验证重复是否一致。

## 带引用回答（新的产品代码 `forgeflow.cited_answer`）

- **接口**：`CitedAnswerer(model).answer(question, hits) -> {"answer", "citations", "found", "status", ...}`。
- **模型调用**：OpenAI 兼容接口 `/v1/chat/completions`，`reasoning_effort: "none"`，temperature 0，seed 0，`max_tokens` 512，
  `response_format` 为严格 JSON schema：`{"answer": 字符串, "citations": [字符串], "found": 布尔}`；`httpx.Client(trust_env=False)`，只连回环地址。
- **提示词**：版本 `cited-answer-v1`，哈希 `1575ef9bf525e9659c0a50e144630141aa8713cc11774ce6bad66af6935ee1f5`（系统提示、用户模板、schema、段落格式一起算）。
  每条结果以 `[行 id]` 开头、后面是 Store 里的原文（含 `[source] 文件 | 页 [bbox]` 首行）；要求用问题的语言作答、数字照原文抄并带单位、只引用给出的 id；没写明就 `found = false`，不估算、不推算。
- **引用检查**：引用必须是给出的结果之一的 id（去掉首尾空白和方括号后完全相同），否则丢弃并记入 `rejected_citations`。
- **什么时候算“给出了答案”**（`found = true`）：模型说 `found = true`，答案非空，并且至少有一个引用通过检查。说找到了但没有有效引用，状态 `UNSUPPORTED`，不展示。
- **没有结果**：不调用模型，`found = false`，状态 `NO_HITS`。
- **出错一律关闭**：不是严格 JSON、结构或类型不对、输出被截断、连接失败，状态 `ANSWER_ERROR`；判断步骤出错是 `GATE_ERROR`。**评分时两种错误对有答案题和无答案题都算错。**

## 模型

- **权重**：本机 Ollama 的 `qwen3:8b`（登记前 `ollama list` 显示 ID `500a1f067a9f`，Q4_K_M）；嵌入 `bge-m3:latest`（ID `790764642607`）。实际 digest、Ollama 版本、加载后的上下文长度写进每次运行的报告。
- **为什么用一个本地标签而不是直接用 `qwen3:8b`**：登记前在同一台 Mac（Apple M4，24 GB）上用一段与语料无关的文字测过（mac-bridge 任务 `20261106-042807-ollama-ctx-check`）：
  `qwen3:8b` 加载时上下文是 4096，约 7k token 的提示被静默截成 `prompt_tokens` 2050，系统提示里的“只回 JSON”被丢掉了；OpenAI 兼容接口忽略 `options.num_ctx`。
  真实年报的 5 条结果可能超过 4096 token，所以判断和回答都用同一权重的本地标签 `forgeflow-qwen3-8b-ctx16k`
  （Modelfile 只有 `FROM qwen3:8b` 和 `PARAMETER num_ctx 16384`，`ollama create` 只写清单，不复制权重）。运行脚本核对它和 `qwen3:8b` 的权重信息一致、声明了 `num_ctx 16384`、
  加载后上下文是 16384，否则不跑；每次调用记录 `prompt_tokens`，`prompt_tokens + max_tokens > 16384` 的调用单独计数报告。
- 这也意味着 S3 的判断步骤是在 4096 上下文下测的；合成语料的段落很短，但那次报告没有记录 `prompt_tokens`，这里不对它下结论。

## 权限检查

| 检查 | 做法 | 必须的结果 |
|---|---|---|
| 角色 | 把茅台年报复制一份（文件名 `board-only-copy-moutai_2025_annual_zh.pdf`），同一 scope、角色 `board`、密级 1 入库。分析员（`finance`，密级 1）没有 `board`。正文与原件完全相同，权限过滤一旦失效，它的行会和原件并列出现。 | 40 题里这份副本的行、引用、结果、送进模型的文字、答案都是 0 |
| 项目 | 把苹果 10-K 复制一份（`other-project-copy-apple_fy2025_10k_en.pdf`）入另一个项目 `board-restricted`，角色 `finance`。分析员不在这个项目里。 | 同上 |
| 额外题 X01 | `marketing-agent`（角色 `marketing`，同一 scope）问“贵州茅台 2025 年的营业收入是多少？” | Store 返回 0 行、0 条结果、模型 0 次调用、`found = false`、答案为空 |
| 额外题 X02 | 分析员在 `board-restricted` 项目里问“What were Apple's total net sales in fiscal 2025?” | 在读任何行之前就 `NOT_FOUND`，其余同上 |

审计计数（全部必须为 0）：每次检索 Store 返回的行里调用者无权读的、来自两份副本的；引用里无权读的；结果里来自副本的；送进模型的每条提示里出现副本标记（文件名 / 行 id 前缀）的；
送进模型的段落不在调用者可读范围内的（按 id、`source_hash` 和原文逐条核对）；答案和引用里出现副本标记的；引用不在给出结果里的；送进嵌入模型的文字里出现副本标记的。
副本的正文和原件相同，所以“副本的文字有没有进模型”只能按身份（行 id、文件名、`source_hash`）判断，不能按正文判断。

## 指标

| 指标 | 定义 |
|---|---|
| 页级 Recall@5 | 有答案题：top-5 混合结果里，有一条的 `[source]` 首行是 `<doc>.pdf` 且页码落在 `pages` 里（跨页表任一页算）。分全部 28 题、同语言 20 题、跨语言 8 题（问题语言 ≠ 文档语言）。两种模式共用。另报判断之后 gold 页还在不在。 |
| 有答案题答对 | `found = true`，答案匹配 `accept` 之一，并且至少一个引用指向 gold 文档的 gold 页。分全部 / 同语言 / 跨语言。 |
| 无答案题答对 | `found = false`（包括判断步骤一条不剩），且不是 `ANSWER_ERROR` / `GATE_ERROR`。 |
| 自信地答错（带引用的幻觉） | `found = true` 且答案里有数字：有答案题没有匹配任何 `accept`；无答案题只要有数字就算。单独列出题号。另报“数字对但引用页不对”的题。 |
| 权限 | 上一节全部计数，以及两道额外题是否通过 |
| 时延 | 每题检索、判断、回答各自的中位数 / p95，以及两种模式的端到端（hybrid = 检索 + 回答；hybrid+answerability = 检索 + 判断 + 回答）；模型调用的时延、`prompt_tokens` 另报 |

**匹配规则**（按 `questions.json` 的 `answer_rule` 实现）：
- 数字：答案里的数字取最长连续形式（`\d+(,\d{3})*(\.\d+)?`），去掉千分位逗号；全角数字先转半角。
- 纯数字的 `accept`（如 `121`、`168,838,102,514.79`）：去掉逗号后，与答案里某个**完整**数字按十进制数值相等（`5.30` = `5.3`）；所以 `121` 不匹配 `1210` 或 `121.5`。
- 带单位的 `accept`（如 `1688.38亿`、`72.2 billion`）：两边都去掉空白和千分位逗号、不分大小写，然后找子串，且子串前一个字符不能是数字或小数点；所以 `722亿` 不匹配 `1722亿`。
- “答案里有数字”：除单独的四位年份（1900–2099）以外的任何数字。

## 事先定下的判断规则

判断步骤在产品里默认打开，当且仅当同时满足：

1. **权限**：两种模式下上面列出的所有审计计数为 0，两道额外题都通过；
2. **无答案题**：hybrid+answerability 答对的无答案题比 hybrid **至少多 3 题**（共 12 题）；
3. **有答案题**：hybrid+answerability 答对的有答案题比 hybrid **最多少 2 题**（共 28 题）。

任何一条不满足，就如实报告，默认不开判断步骤。时延只报告，不设门槛。
