# 向量 / 混合检索对比：预先登记

写于第一次真实向量检索之前，与代码同一次提交；提交时间就是登记时间。之后不改本文件，改动另起新版本并保留旧结果。

## 要回答的问题

词法基线（`runs/20261005T170825-lexical-v1-891375a5`）在同一冻结题集上漏掉 8 题：英文同义表达 0/4、跨中英文 0/4。语义检索能不能找回它们，同时不丢精确词/ID 命中、不放宽权限、不在无答案问题上多塞无关上下文？

## 固定不变的部分

- 题集、gold、评测器：`dataset.json`、`evaluator.py` 等冻结文件逐字节核对 `freeze.json`，不一致就不运行。
- 权限和引用链：与 S1 相同，Store 先按角色、密级、scope 过滤，再排序，再逐条重新授权引用。`forgeflow.retrieval.RankedKnowledgeService` 只替换“排序”这一步；`context.py` 不动。
- **嵌入只对调用者有权读的内容计算。** 测试 `test_the_embedder_only_ever_sees_content_the_caller_may_read` 对 47 题逐题核对发给嵌入模型的每一段文字。
- 词法模式必须逐题复现 2026-10-05 的封存结果（返回的 id、版本、hash、状态完全一致），否则不报告向量和混合的任何数字。S1 封存后有 9 个文件改过（检索路径里只是时钟来源和新增夹具 id），8 个原始材料文件不在仓库里；这两点在报告里如实列出，用逐题复现代替“文件未改动”的声明。

## 三种模式与参数（现在定，不看结果调）

| 模式 | 做法 | 参数 |
|---|---|---|
| lexical | S1 原样的词面重叠 + 精确短语/ID 加分 | 无 |
| vector | 查询与每条已授权内容的余弦相似度，低于下限的不返回 | 模型 `bge-m3`（本机 Ollama，不出本机），下限 0.50 |
| hybrid | 词法与向量两份排名做 RRF 融合：每条得分 = Σ 1/(k + 名次) | k = 60（Cormack 等 2009 年的常用值），向量部分同样用 0.50 下限 |

- 选 `bge-m3`：语料和问题中英混合，需要一个多语种模型；它是常用的开源多语种嵌入模型，能在本机跑。
- 下限 0.50 是按这类模型的一般经验定的，没有在本题集上试过。为了事后能看清阈值的影响，向量模式另存每题全部候选的相似度（`similarities.jsonl`）；基于它的阈值分析只算探索性结果，不替换主结果。
- top_k = 5，重复 5 次测时延，与冻结协议相同。

## 主要指标

全部正例与内容正例的 macro Recall@5 / MRR@5；同义 0/4 和跨语种 0/4 两个切片；精确词/ID 切片；无答案问题返回非空上下文的比例（词法为 1/3）；越权泄漏与越权候选观测（必须保持 0）；时延（含查询嵌入调用）。

## 事先定下的判断规则

混合检索可以作为默认候选，当且仅当同时满足：

1. 越权泄漏 0/47，越权候选与引用观测都为 0；
2. 内容正例 Recall@5 不低于词法的 73.33%；
3. 精确词/ID 题不退步；
4. 无答案问题非空上下文不多于词法的 1/3。

任何一条不满足，就如实报告，默认仍用词法。向量单独模式只作对照，不作为默认候选。

## 不能宣称的

- 这个题集小、合成、事先指定，tags 有重叠；跑完这次对比后，它就不再是“没见过的” heldout。之后若根据结果调阈值或 k，必须另建新题集再验证。
- 不代表真实硬件资料、生产规模或回答质量；没有调用 LLM，不报告幻觉率。
- 冲突检测（两条矛盾来源）不是检索排序能解决的，本次不改，照旧报告 0/2。
