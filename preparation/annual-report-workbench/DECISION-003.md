# 研究员怎样带走可以复核的草稿

同一个已核结论，有人希望打印阅读，有人需要把原始事实交给评测，有人还要接手修改。以下为 Codex 代拟的方案，用户尚未在十个选项中表态。

|选项|用户获得的交付物|取舍|
|---|---|---|
|1. 复制结论文本|立即粘贴进会议笔记|丢失原格与版本，做对照。|
|2. HTML 阅读稿|离线阅读问题、分母和引文|便于复核，用作对照。|
|3. JSON 证据清单|机器读取来源、输入、公式和摘要|面向工具，阅读体验较弱，用作对照。|
|4. 同一稿件的可读版本和机器清单|分析师和评测人员按同一版本复核|需要保持两个视图的摘要一致，候选。|
|5. 复制整份 PDF 附件|断网也能看所有页|文件大，可能扩大敏感资料的可见范围。|
|6. 仅保存后端任务 ID|记录最小|缓存过期后难以复盘。|
|7. 浏览器长期保留所有草稿|可恢复上次浏览|共享电脑的本地数据隔离和清理需另行处理。|
|8. 服务端多人审批库|可跨设备协作|需要明确研究身份、审批范围与存储方案。|
|9. 发布共享链接|协作方便|有外部发布和访问控制成本，超出本地交付。|
|10. 生成带签章的最终报告|适合正式签收|必须由有权审阅人对具体版本作有效决定。|

先用同一份 FY2025 公开开发结果、同一预算比较文本、可读稿和可验证数据。记录能否找到具体页、重算分母、检验版本与识别草稿状态。验收采用机器与本地浏览器检查，独立用户体验留待真实试用。

## 实测与选择

同一次已校验 Apple FY2025 查表，三个视图都使用相同内存中的第一版资料，均为零模型调用。每格来自本次程序检查。原始记录见 [review-dev.json](review-dev.json)。

|形式|本轮 UTF-8 字节|完整 PDF 指纹|四个原格金额|版本摘要|
|---|---:|---|---|---|
|复制结论|165|无|无|无|
|HTML 阅读稿|2,864|有|有|有|
|JSON 清单|3,869|有|有|有|

结论文本保留了两组分子与分母，足以再算百分比。它缺少两年各自的服务收入和公司总收入，接手人无法从中核对分母的来源。HTML 可以离线阅读，JSON 可以按字段重新计算。Codex 选用第 4 项，把两个文件都绑定到同一个版本摘要。文件摘要随内容与审阅记录变化，字节数随时间戳和数据而变。

用户随后授权本机持久化与双身份审阅，稿件直接保存在服务端的独立 SQLite 库。浏览器关闭后可以重新登录继续。同一用户的凭证只在当前页面内存中使用。其他形式没有做产品试用。两个可下载样例为 [第二版阅读稿](apple-review-v2.html) 和 [第二版事实清单](apple-review-v2.json)。
