# 年报问答的本机性能边界

## 目标

把“索引很慢”和“提问很慢”拆成可复跑的本地测量：首次解析、复用同一 PDF 指纹的解析缓存、同题重复、异题顺序调用，以及同一进程中的三请求并发。每个记录保留请求文本、保留的检索行、最终引用和回答摘要。每个并发请求都必须与其对应的顺序同题基线逐项相同；不只比对问题回显，避免把交叉响应当作成功。

## 取舍

本轮强制使用不可达的 Ollama 地址，因此只走词面检索且 `answerer=None`。这让四份公开年报、SQLite、真实 PDF 解析缓存和 `ReportDesk.ask` 都可测，却不把模型加载、向量嵌入、聊天生成、Redis、RabbitMQ、gRPC 或 HTTP 网络混在结果中。它是开发机的组件基准，不是并发容量、P95 服务承诺或真实用户试用。

## 复现

```text
PYTHONPATH=src /Users/ju.l/code/forgeflow-desk/.venv-mac/bin/python \
  scripts/report_desk_perf_dev.py /Users/ju.l/code/finreports /tmp/forgeflow-report-desk-perf.json
```

输出中的 `cold_load_ms` 从空的解析缓存开始；`warm_load_ms` 从同一运行内复制的、以 PDF SHA-256 命名的缓存开始。两者均会重新创建 SQLite 和检索服务，因而不应被解读为进程常驻后的 HTTP 缓存命中。后续若运行完整 desk service，应另行记录模型、队列、服务进程、机器负载和端到端事件时间，不能与此文件直接合并。

## 本轮实测

`report-desk-perf-dev.json`归档四份公开年报、6,425段内容。空解析缓存加载38,887.0毫秒，复用解析缓存9,778.8毫秒。这是一次配对测量，不能作为普遍加速比例。

同题3次P50为1,011.9毫秒，异题4次P50为1,096.6毫秒，三请求同进程并发约3,251.1–3,254.0毫秒/请求。并发结果逐一匹配顺序同题的状态、检索行、引用及回答摘要。并发在本次负载下没有提速；未分析GIL、锁或其他因素的独立贡献。小样本P95近似样本最大值，不构成服务SLA。

本次没有答案缓存；重复提问不代表答案缓存命中。无模型分支下部分问题仅检索、不生成最终答案，不能将10次调用计作10次任务成功。此模块用于拆分和复现耗时边界，完整模型服务性能仍待测。
