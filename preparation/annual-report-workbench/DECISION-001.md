# 分析师怎样发现季度数误填全年

这是 Codex 代做的开发实验与暂定推荐。业务负责人尚未对十个选项逐一表态。输入是公开开发样例，不能充当独立留出集。

|做法|使用者得到什么|取舍与本轮决定|
|---|---|---|
|1. 回到引用页自己找|能核对任意问题|当前页面已有。面对没有表头的续页，分析师仍需翻上一页。保留作历史对照。|
|2. 按指标行取第一个数|能很快看到候选值|便宜，列序一变或查询上年就会错。实跑。|
|3. 精确匹配指标、年份列和货币单位|能看到取数行、列和原始单位|可能错过丢列头的真证据。实跑。|
|4. 在多处年度披露里交叉核对|可看到重复披露；数值矛盾时退回核查|单一披露的真值可能因强制双证据被拒。实跑单证据和双证据门槛。|
|5. 四季求和再推算全年|可从分季度表得出有解释的候选|可能遇到重述、单位不明、累计口径；未试。|
|6. 还原跨页列头|直接看上下页是否同一张季度表|需检测跨表、页脚和列位偏移；未试。|
|7. 要模型先复述单位和表头|可照顾自然语言长尾|增加推理开销，模型也可能补造表头；未试。|
|8. 用视觉模型复读原页局部|保留文本层没读到的表格关系|成本和可重复性需单独量；未试。|
|9. 让分析师在表格中手选年份列|几乎所有可读表都能人工完成|增加人工步骤，适合缺证据的恢复路径；未试。|
|10. 对照附注或结构化公告数据|有另一种抽取来源|需要版本、会计准则与期间对齐；未试。|

三种策略共享各请求的同一份候选清单、文档版本和顺序，最多展示五个候选，均不调用模型。另列已保存的真模型历史回答，其输入上下文与耗时不参与等预算对比。产品优先保证期间可证、单位明确、可点击原表；独立判分归 EvidenceLoop。

## 实际结果

用源码目录加入 PYTHONPATH 的项目 Python 执行 `scripts/annual_cash_dev.py ~/code/finreports <输出文件>`。脚本先按清单校验 PDF，重新解析入临时 SQLite，再向 FastAPI 正常路由发请求。实验和产品均无模型调用。原始候选、引用矩形和逐请求耗时见 [annual-cash-dev.json](annual-cash-dev.json)。

|请求年度|只读指标行的第一格|明确年度列＋单位|再要求两处披露|
|---|---:|---:|---:|
|2025|32,868,257|133,219,982（页 11、30）|同左|
|2024|32,868,257|96,990,345（页 11、30）|同左|
|2023|32,868,257|92,826,124（页 11）|待核|
|2022|32,868,257|待核|待核|

单位均按年报原页为人民币千元。第一个候选刻意取历史错答所在的季度页，以复现排序暴露的风险；这个确定性对照取首格，历史真模型实际取了末格 52,559,552。不同年度是同一文档的公开开发输入，不能据此估计整体准确率。

Codex 暂选明确年度列和单位、所有可见合格候选一致才呈现。多处原表披露是同一公司的重复披露。引文颜色框现阶段显示整张表。对未识别的自然语言提问仍走原问答链；此迭代只覆盖宁德时代这份特定公开报告的年度经营现金流精确查数。权限、冲突、缺列、单季输入与 worker 无模型分支由回归覆盖。独立判分与真人试用待验。

代码复核时发现两处年度披露冲突会导致用户拿不到原表。现已保留两个经权限与引用校验的冲突候选，即使仅请求一个答案也能分别打开候选。新增回归使用真实回环 gRPC 和 worker，Redis 事件写入及入队消息为替身，同时核对一致与冲突的 final 事件；该回归不代表新版本在真实消息队列上完成过负载测试。
