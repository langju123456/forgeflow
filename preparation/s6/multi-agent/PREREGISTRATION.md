# 年报问答多角色编排：预先登记

写于编排代码、运行脚本和留出题之前，单独一次提交；提交时间就是登记时间。
机器可读的版本是 [preregistered.json](preregistered.json)，运行脚本读它，核对题集、模型设置和提示词哈希，不一致就不跑。
之后不改本文件，改动另起新版本并保留旧结果。

登记时还没有的三样东西，各自在第一次用到之前单独提交，运行脚本逐项核对：

| 东西 | 记在哪 | 什么时候定 |
|---|---|---|
| 各角色的提示词、输出 schema、编排版本 | `pins.json`（哈希） | 可以在开发集上改，每次改都提交；以留出题运行之前最后一次提交为准 |
| 留出题（题目、gold 页、可接受的写法） | `heldout.json` + `heldout-freeze.json`（哈希、核对人、时间） | 人工逐题对过年报原页之后冻结；早于在这批题上的任何检索或模型调用 |
| 编排代码 | 运行报告里的文件哈希和提交号 | 留出题运行之前 |

## 要回答的问题

S4 在四份真实年报上测过单次回答：有答案题 13/28，无答案题 7/12，自信地答错 14 次；在检索和回答之间加一步模型判断，没达到事先定的条件，没有采用
（[S4 结果](../../s4/real-reports/RESULTS.md)）。那次的自信答错主要是三类：没有表头的续表数字被安上了问题里的含义、引用了别家公司的段落、同一张表里的另一个指标。

这次问：回答之后再加角色，能不能多答对、少答错。要分开两件事：

- 多调用一次模型本身有没有用（同一个角色再看一遍自己的答案）；
- 换一个只看答案和被引原文、只能否决的角色，比同一个角色自己再看一遍，多出来多少。

## 固定不变的部分（沿用 S4 登记，不重新定）

语料、入库、scope 和身份、混合检索（`bge-m3`、余弦下限 0.50、RRF k = 60、top_k = 5）、权限顺序、带引用回答的提示词 `cited-answer-v1`、评分规则，
全部按 [S4 的 preregistered.json](../../s4/real-reports/preregistered.json)（sha256 `1a1f28389087184b7b70c3bfa85b6fa78aa389e85775125cb4bbb0511b03e828`）原样使用；
运行脚本直接调用 S4 的入库、检索和评分函数，不另写一套。

- **模型**：四组、所有角色都用本机 Ollama 的 `forgeflow-qwen3-8b-ctx16k`（`qwen3:8b` 的同一份权重加 `num_ctx 16384`）。
  不用原标签 `qwen3:8b`：它加载时上下文是 4096，超过的提示会被静默截断（S4 登记里的传输检查）。运行脚本核对权重一致、声明了 `num_ctx 16384`、加载后的上下文是 16384，否则不跑。
- **调用设置**：OpenAI 兼容接口，`reasoning_effort: "none"`，temperature 0，seed 0，`max_tokens` 512，严格 JSON schema；只连回环地址。
- **权限顺序**：Store 先按角色、密级、scope 过滤 → 排序 → 逐条重新授权引用 → 之后才轮到任何角色。每个角色只拿到检索已经返回给这个提问者的结果或其中一部分；
  规划者不看语料，只看问题和报告清单（文件 key、公司名、文档名、语言）。

## 四组

| 组 | 做法 | 每题模型调用 |
|---|---|---|
| single 单次回答（重跑） | 检索 top-5 → 执行者回答一次。就是 S4 的 hybrid 模式，在这次运行里重跑，不拿旧数字来比 | 0–1 |
| self_check 单 Agent 自检 | 同上；首答给出了答案时，**同一个角色**（同一个系统提示、同样看到全部 5 段）再调用一次：看着自己的答案按核对清单检查，原样保留、改掉或者收回 | 0–2 |
| verify（A）执行者 + 核对者 | 同上；首答给出了答案时交给核对者。通过就结束；否决后执行者带着否决的类别重答一次，再交核对者；再否决标“待核”，不展示答案 | 0–4 |
| plan_verify（B）规划者 + A | 规划者先看问题，拆出公司、指标、期间，并改写检索词；按计划检索（公司对应的那份报告内，用改写后的检索词），之后与 A 完全相同。计划无效就退回原检索 | 1–5 |

没有结果（检索 0 条）时四组都不调用模型，直接“没有”。首答没给出答案（`NOT_FOUND`、`UNSUPPORTED`、`ANSWER_ERROR`）时，自检组和 A 组都不再调用：没有答案可查。

不做 supervisor 动态路由（让模型决定下一步交给谁）：步骤顺序由代码固定。

### 角色能看到什么、能做什么

| 角色 | 看到 | 交出 | 权限 |
|---|---|---|---|
| 规划者 planner | 问题；报告清单 | 公司（清单里的 key 或空）、指标、期间、检索词 | 只影响检索范围和检索词，不回答 |
| 执行者 executor | 问题；检索结果；重答时另加被否决的答案、它引用的 id、否决类别 | 答案、引用的 id、是否找到 | 回答或者说没有；只能引用给它的结果 |
| 核对者 verifier | 问题；答案；**答案引用的那几段原文**（不给其余结果，不给执行者的其他输出） | 通过 / 否决、否决类别（公司、指标、期间、数字）、通过时的逐字引文 | 只能否决；不能改答案、不能加引用 |

自检组和核对者用同一份核对清单（公司对不对、指标对不对、期间对不对、数字是不是原文印的），文字相同。
这样自检组和 A 组的差别只剩：是不是另一个角色、看到的是全部结果还是只有被引原文、能改还是只能否决。

### 冲突时听谁的

代码校验 > 核对者 > 执行者。

- 执行者的输出先过 `cited_answer` 原有的检查（严格 JSON、引用必须是给它的结果、说找到了就必须有非空答案和至少一个有效引用）。不过关就没有答案可核，核对者不被调用。
- 核对者的输出也先过代码：不是严格 JSON、结构或取值不对，记 `VERIFY_ERROR`，答案不展示。
  只有“通过、没有不合格的项、引文至少 6 个字符并且逐字出现在被引原文里”三样都成立才算通过；说通过但引文对不上，按否决处理。
- 核对者否决，执行者的答案就不展示，即使执行者坚持。
- 规划者的计划先过代码：不是严格 JSON、公司不在清单里、指标或检索词为空、检索词超长，或者按计划检索 0 条，都退回原检索。规划者出错不影响后面，只是没用上计划。

### 出错怎么算

- `ANSWER_ERROR`（回答或自检的输出不合格、被截断、连接失败）和 `VERIFY_ERROR`：**评分时对有答案题和无答案题都算错**，与 S4 相同。
- “待核”（`NEEDS_REVIEW`）不是出错：答案不展示。有答案题算没答对，不算自信答错；无答案题按“没有给出答案”算对。各组的待核题数按题型单独报告，读结果时能看出无答案题答对里有多少来自待核。
- 重答和被否决的答案完全相同（文字和引用都相同）时，不再调用核对者，直接标待核：同样的输入在 temperature 0 下得到同样的否决。

### 恢复

产品路径上沿用现有的任务级机制：任务至少投递一次，最后才 ack；任务重投时整条编排从头再做，不做步骤级断点。缓存键加入编排方式和编排提示词哈希，四种方式互不共用缓存。

## 同一批题

| 题集 | 用途 |
|---|---|
| 开发集：S4 冻结的 40 题（`preparation/s4/real-reports/questions.json`，sha256 `68f83bf6…`，不改） | 已经用过，只用来调提示词和查流程；结果作为探索性结果报告，不参与判断 |
| 留出题：新写的 40 题（有答案 28，其中 8 道跨语言；无答案 12），每份报告 7 道有答案 + 3 道无答案，与开发集的构成相同 | 判断只看它 |

留出题的要求：不问开发集已经问过的“同一家公司的同一个指标”；不触发年报问答里已有的两个确定性查表工具（那两类问题不经过模型）；
gold 页由脚本从 PDF 页面文字里初标，逐题标“待人工核对”，人对着原页核过才能冻结；冻结之后才允许在这批题上检索或调用模型。留出题只正式跑一次。

四组在同一次运行里回答同一批题，每题的顺序固定：检索 → 首答 → 自检 → 核对（→ 重答 → 再核对）→ 规划 → 按计划检索 → B 的首答和核对。

**同一提示词只真正调用一次。** 一次运行里，消息和 schema 完全相同的调用只发给模型一次，结果在各组之间共用：single、self_check、verify 三组的首答就是同一次调用；
B 组退回原检索、或者按计划检索到的结果与原检索完全相同时，它的首答和后续步骤也是同一批调用。这样各组的差别只来自各自多出来的步骤，不来自同一提示词两次调用之间的波动
（temperature 0、seed 0 下两次调用是否逐字相同，这次仍然不验证）。各组的调用次数和耗时，按这一组单独运行时会发生的调用来计。
运行中断后重跑同一条命令，会接着磁盘上的调用记录往下做，已经完成的调用不重复。

## 指标

按 S4 登记的评分规则（数字按完整数字比对、带单位的写法按有边界的子串、引用要落在 gold 文档的 gold 页），每组、每个题集分别报告：

| 指标 | 定义 |
|---|---|
| 有答案题答对数 | 给出了答案，匹配 `accept` 之一，并且至少一个引用落在 gold 页。另分同语言 / 跨语言 |
| 无答案题答对数 | 没有给出答案，且不是 `ANSWER_ERROR` / `VERIFY_ERROR` |
| 自信答错数 | 给出了带数字的答案：有答案题没有匹配任何 `accept`；无答案题只要有数字就算。列出题号 |
| 每题调用次数 | 模型调用次数的合计、平均、中位数、最大值；按步骤（规划、首答、自检、核对、重答、再核对）分别计数 |
| 每题耗时 | 检索 + 这一组全部模型调用的耗时，中位数 / p95；B 组另加按计划检索的耗时 |
| 失败类型 | 没答对的每一题归一类：检索没带回 gold 页而说没有；gold 页在结果里但说没有；数字错（gold 页在 / 不在结果里）；数字对但引用页不对；给了答案但没有数字；待核；出错（按状态）。无答案题：编了带数字的答案；给了不带数字的答案；出错 |
| 核对者 | 通过 / 否决（按类别）/ 引文对不上 / 出错的次数；否决之后重答变成了什么 |
| 规划者 | 计划被采用 / 无效（按原因）/ 检索 0 条退回的次数；按计划检索后 gold 页在不在 top-5，与原检索对比 |
| 另记两个不参与判断的标记 | 答案引用了别的公司的报告；答案里有被引原文里没有印的数字。四组都记，只用来看失败类型，不拦答案 |
| 权限 | 每次检索 Store 返回的行里提问者无权读的、来自受限副本的；送进模型的每条提示里出现受限副本标记的；送进模型的段落不在提问者可读范围内的；引用不在给出结果里的。全部必须为 0 |

## 事先定下的采用条件

只看留出题。A 和 B 各自判断。一组算“采用”，当且仅当同时满足：

1. 有答案题答对数比 single **至少多 3 题**（共 28 题）；
2. 有答案题答对数比 self_check **至少多 2 题**；
3. 自信答错数（有答案题 + 无答案题合计）**不多于** single；
4. 权限一节的计数全部为 0。

任何一条不满足，记“不采用”，如实报告，产品里默认仍是单次回答，编排保留为需要显式打开的选项。
A 和 B 都满足时，采用有答案题答对更多的那组；一样多就采用 A（调用更少）。
无答案题答对数、调用次数和耗时只报告，不设门槛。开发集上的结果不参与判断。

## 不在这次范围里

- 多角色给出的答案不进入入稿审批：入稿仍然只接受两个确定性查表工具、带调用轨迹的结果。
- 不改 MCP 工具；不做动态路由；不换模型，不比较不同模型担任不同角色。
- B 组只在进程内的年报问答和评测脚本里可用；服务化的 worker 这一轮只接 self_check 和 verify（gRPC 检索接口没有“限定报告、换检索词”的字段，这次不改接口）。

## 不能宣称的

- 题目、gold 的初标、匹配规则和被测代码出自同一作者；核对者的清单是看过开发集的失败之后写的。留出题写的时候作者看不到年报全文：
  候选题按披露规则里的固定栏目写，由脚本到 PDF 页面文字里定位，人工核对的是“题目问的是不是这一格、页码和数字对不对”，不是题目选得有没有代表性。
- 40 题：有答案题 1 题 = 3.6 个百分点，无答案题 1 题 = 8.3 个百分点。采用条件差的是 2–3 道题，一两题的波动就会改变结论。
- 单一模型（8B，4 位量化）同时担任所有角色、单台笔记本、单次运行；不代表更强的模型当核对者、别的文档或真实用户的问题分布。
- 自检组最多多 1 次调用，A 组最多多 3 次，两组的调用次数并不相等；“多一个角色”的差别里含有这部分。调用次数逐组报告。
- 同一提示词的调用在各组间共用，等于假定同样的输入得到同样的输出；这个假定没有验证。
- 匹配规则对纯数字的 `accept` 不核对单位（S4 结果里已说明）。
- 留出题跑完就用过了；之后若据此改提示词、清单或规则，要另写新题再验证。
